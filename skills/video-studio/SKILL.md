# Video Studio

One idea in, one finished video out. Work the stages in order and stop for approval at each ★. Keep the person informed with a task list.

## Project folder

Create `<videos-root>/<slug>/` (default root: the current working directory) and copy `templates/brief.md` into it:

```
narration.md    approved clean paragraph (niche-strategy handoff only)
brief.md        format, length, persona, hook, spine, Four Decisions, palette, light arc, sound bed, voice sheets
sources.md      every fact with a link; every asset with its licence
script.md       narration lines `s01_l01: …` (`s01_l02 [NAME]: …` for a cast voice) with delivery cues
shots.json      art direction: aspect, style, eras, character sheets, one prompt per shot (source of truth)
shotlist.md     beats, then one row per shot in frames + the delivery-cue table (generated by scripts/plan.py)
cues.md         SFX/music cues in the same frame numbers
art/            prompts.md, prompts.json (generated) + the images, named 01.png, 02.png … by shot id
audio/          voice.json (persona, voice, lead-in, cast), voice/, pronounce.json, voice_timing.json,
                narration_norm.wav, audition/, music/, sfx/, beats.json (silent films)
build/          HyperFrames project or Kazchart scene.json
review/         contact sheets, checks/ (checks.py + cue strips), notes.md
export/         final.mp4, captions.srt, publish.md
```

The folder is the template for the next episode.

## 1. Intake ★

Ask one question if it isn't already clear: **where are we starting?**

- **Approved niche-strategy narration** → record niche, optional subniche, target duration, and source notes. Save the paragraph verbatim in `narration.md` and sources in `sources.md`. Split the approved wording into `sNN_lNN` takes in `script.md` and put cues at line boundaries. Run the stage 3 lint and keep any suggested wording changes separate for approval. Continue at stage 4 without reopening ideas or storylines.
- **Voiceover ready** → ask for the audio and its script text (the text makes timing exact). Go to stage 5.
- **Script ready** → tighten it with stage 3, go to stage 4.
- **A vault script or inspiration note** (`youtube-inspiration`) → convert its voiceover to `script.md` lines (cues kept), its Four Decisions and logline to `brief.md`, its shot table to `shots.json`; then stage 3 (lint), stage 4.
- **Choosing a nature or science niche** → use [niche-strategy](../niche-strategy/SKILL.md). Resume here when the user requests production.
- **Topic only / need ideas** → stage 2.

Also settle: the **format** (`references/formats.md`: explainer, micro-drama Short, silent short film, long-form saga, dialogue cartoon), target length (Short default 20–45 s, max 60 s), the **persona** (`free-voiceover`: explainer, confessor, historian, chronicler, storybook; none for a silent film), narration only or characters who speak, the visual style (offer 2–3 HyperFrames directions if none) and the palette (name the background and accent colours).

Use HyperFrames by default. Offer Kazchart for supported ocean/vector explainers when its existing visuals can represent the subject accurately. Record the renderer in the brief and select `abyss` or `ink` at intake for Kazchart.

## 2. Ideas ★

Follow `references/ideas.md`: exactly 10 numbered ideas (title, format + hook archetype, hook line, twist, why it animates, true/disputed/legend), facts verified first. Person picks a number.

## 3. Story and script ★

- Read `references/story-and-script.md` and the format's section of `references/formats.md`. Fill `brief.md`: premise, controlling idea, want-vs-misbelief, the ending first, and for story formats the Four Decisions.
- ★ Offer 3 storylines (hook archetype + hook line, a 3-line spine, the ending line); the person picks one.
- Research facts into `sources.md`; flag anything unverified. The person checks sources.
- Characters who speak → also read `references/dialogue.md` and write a voice sheet per character in `brief.md`.
- Write `script.md` with delivery cues (every scene at least one; exactly one `*(dry — cut music)*`, on the turn), then run the lint until it is clean:

```bash
python3 -I ~/.claude/skills/video-studio/scripts/lint_script.py script.md --seconds <target> [--persona <name>]
```

- Run the craft check (`story-and-script.md` §8) for what the lint can't see.
- Show: the script in a copyable block with word count and estimated length, a one-paragraph visual plan (shots, light arc, sound bed), and the beat list.
- After approval, offer once to file the script in the Obsidian vault (`youtube-inspiration`); file it only on yes.

## 4. Voice

- Default: `free-voiceover` (Kokoro). Write `audio/voice.json` (`persona`, `lead_in` 2.0 for a micro-drama Short, `cast` for other voices), audition (`voice.py --project . --audition`), let the person pick, then `voice.py --project .` voices every `sNN_lNN` line, performs the cues, measures it all and writes `audio/voice_timing.json` + `audio/narration_norm.wav`. Paid voices only when the person asks.
- If the person records their own voice, give recording tips: one steady warm voice, natural pauses at sentence ends, the beats held, export without music, wav or mp3.
- Never edit or re-time a recorded voice; the picture is timed to it.
- Silent film: no voice. Pick the music first and run `npx hyperframes beats audio/music/<track> --json > audio/beats.json`.

## 5. Shot plan

For Kazchart, follow [the Kazchart production route](references/kazchart-production.md) for stages 5–6, then resume at review.

Read `references/shots-and-sound.md`. Time from measured per-line durations (or `npx hyperframes transcribe`). Write `shots.json` (with `"aspect"`), then `shotlist.md` (beats, then one row per shot in frames, then the delivery-cue table) and `cues.md` before building. Story formats: plan the light arc (cold eras → warm eras at the turn).

## 5b. Art (when the person makes the images, e.g. in ChatGPT) ★

Use this when the look needs illustrated or photographic stills and the person generates them themselves instead of paying for image generation. Details and prompt rules: `references/shots-and-sound.md` § Art board.

1. Write `shots.json`: `title`, `aspect` (`16:9` or `9:16`), one shared `style`, `eras` (palette notes; `cold`/`warm` for story formats), `characters` (appearance only), and one shot per 1–3 narration lines (`id`, `lines` like `s01_l04-s01_l05`, `era`, `move`, `overlay`, `prompt`, characters tagged at the end as `(ENZO_OLD)` or `(ENZO_YOUNG age 25, PAOLINA)`). Shots without narration (a Short's 2 s hand hook, its loop shot, silent-film shots) have `sec` (or `beats`) instead of `lines`.
2. Generate the timed files: `python3 ~/.claude/skills/video-studio/scripts/plan.py --project <dir> [--beats audio/beats.json]` → `shotlist.md`, `art/prompts.md`, `art/prompts.json`. Re-run after any change to the voice or `shots.json`.
3. Start the art board in the background: `python3 ~/.claude/skills/video-studio/scripts/art_server.py --project <dir> [--port 8765]`. Give the person `http://127.0.0.1:8765`: per shot it shows the narration and a **Copy prompt** button, and takes a pasted (Cmd+V), dropped or chosen image, saving it as `art/<id>.png|jpg|webp`. `art/prompts.md` is the no-server fallback.
4. Wait for the person to say the images are in. Missing shots get a placeholder in the build; list them.

## 6. Build (HyperFrames)

| Need | Skill |
|---|---|
| Scenes, captions, music/SFX/stock, grades | `hyperframes`, `media-use` |
| Copy the grammar of a reference video (never its content) | `reverse-any-video` |
| CLI: preview, check, snapshot, render, transcribe, timeline edits | `hyperframes-cli` |
| Blocks and components | `hyperframes-registry` |

Build scene by scene; each delivery-cue action lands on its frame from `shotlist.md`. Sound: get the music and foley (`media-use`), then `python3 ~/.claude/skills/video-studio/scripts/audio_bed.py --project . --music … --ambience … --inject` (the 3-layer bed). Before the long render: `npx hyperframes check build --json` (fix every error), `npx hyperframes snapshot build --at <the cue times printed in shotlist.md>`, then send a stills contact sheet with a one-line shot summary.

## 7. Review ★

Run `video-review-loop`. For Kazchart, use its renderer for previews and range renders, and start the shared review at §1. Run `scripts/checks.py` (`--short` for Shorts, `--warm-ending` for story formats, `--project .` for the cue strips). Fix order: wrong/missing → readability → timing → visual detail. Re-render only changed ranges.

## 8. Package

- Captions from the final narration (`npx hyperframes transcribe audio/narration_norm.wav --to srt -o export/captions.srt`), not an old SRT; fix names against `script.md`. Story Shorts: burned-in captions only if the person wants them.
- Shorts from a long-form: `shorts-from-longform`.
- Upload kit: `youtube-publish-kit` (packaging matrix, description, pinned comment, settings).

## Rules that keep a channel alive

- Original stories, characters and shots. Reimagine, never recreate: take the grammar of other videos (hook type, structure, pacing, light, sound), never their characters, lines, shots, music or art.
- No real living people as characters or jokes, no brand mascots or logos, nothing graphic or political.
- New story, new sets, real sources every episode; YouTube's monetization policy targets mass-produced, repetitive content.
- Disclose realistic synthetic voice/visuals when YouTube asks.
- Only assets licensed for monetized use; log them in `sources.md`.
- After publishing, note where audience retention drops in the next episode's `brief.md`.

Other skills are parked in `~/.claude/skills-disabled/`; suggest moving one back only if the person asks for that capability.
